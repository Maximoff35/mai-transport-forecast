# План мощности

Приложение открывается на текущем прогнозе. Отдельные страницы `/history`, `/retrospective` и `/data` доступны через верхнее меню. CSV-набор сохраняется в браузере и используется после перехода между страницами.

## Запуск

В папке `web` с Node.js 22.13 или новее:

```sh
npm ci
npm run dev
```

Откройте [127.0.0.1:5173](http://127.0.0.1:5173). `npm test` проверяет расчёт, импорт и HTTP-ответы, `npm run typecheck` проверяет типы. Для запуска собранной версии выполните `npm run build`, затем `npm start`. Серверу не нужны внешние ключи.

## Данные аналитика

Встроенный архив содержит 58 кварталов с I квартала 2012 по II квартал 2026 по каждому из трёх бассейнов. Отдельно доступна годовая история России с 1991 по 2025. [Источники и форматы](data/README.md).

Чтобы добавить квартал, скачайте шаблон и укажите бассейн (`baltic`, `azov` или `far_east`), квартал вида `2026-Q3` и объём в **млн т за квартал**. Укажите дату доступности публикации в `published_on` и ссылку в `source_url`, если они известны. При отсутствии даты используется дата импорта с пояснением.

Загрузка открывает предпросмотр. Применение сохраняет рабочий набор в текущем браузере и пересчитывает сценарий. Повторы с тем же значением пропускаются, конфликтующие значения отклоняются. Сохраните оригинальный CSV для переноса на другой компьютер. Набор браузера можно сбросить на исходный. Данные из файлов аналитика помечаются отдельно от проверенных публикаций.

Для каждого планового квартала нужен факт за тот же квартал предыдущего года. Когда требуемых фактов нет, приложение показывает их список. Режим сравнения заранее согласованных действий позволяет посмотреть эффект меры отдельно от текущего календаря.

## API

| Метод | Адрес | Результат |
| --- | --- | --- |
| GET | `/api/catalog` | Бассейны, параметры по умолчанию, демонстрационный пример. |
| GET | `/api/data` | Проверенный исходный набор. |
| GET | `/api/template` | Шаблон для квартального CSV. |
| POST | `/api/import` | Предпросмотр CSV. JSON `{csv, baseDataset?}`. |
| POST | `/api/scenario` | Расчёт. Поля сценария из каталога и необязательное поле `dataset` из предпросмотра. |
| POST | `/api/replay` | Ретроспектива выбранного диапазона и условная денежная оценка. |
| GET | `/api/health` | Состояние сервера. |

В интерфейсе можно выбрать файл до 1 МБ. У запросов импорта и расчёта лимит тела 2 МиБ с учётом параметров и ранее загруженных данных. Сервер проверяет каждую полученную копию. Для автономного показа без сервера используйте `03 Инструмент/Демо.html` из корня проекта.

## Ретроспектива и экономика

Сервер делит выбранный диапазон на непересекающиеся пары кварталов. Для каждой пары берёт последний доступный перед её началом срез и строит сезонный прогноз. В экономическом режиме выбирает доступную меру с максимальным ожидаемым дополнительным вкладом после затрат. Исходный план имеет нулевой дополнительный вклад. Без экономики критерий совпадает с основным планировщиком: минимум прогнозного превышения. Мощности действий и сроки одинаковы в обоих режимах. После выбора подставляется опубликованная перевалка. Пропущенные пары и непарный последний квартал показаны отдельно.

Сравниваются исходный план, выбор по прогнозу и независимое правило «резерв в квартале ремонта». Постоянные мощность, ремонт и резерв являются параметрами эксперимента. Экономический режим переводит разницу дефицита в дополнительный объём через заданную долю, умножает на тариф и вычитает переменные затраты и стоимость мер. При одинаковых ценах для всех лет итог показывает оценку в этих ценах. Без экономических вводных доступны тонны, число назначений и порог сравнения. Открытые тарифы конкретной услуги приведены как пример источника для сверки входов.

Готовый пример: доля 25%, тариф 1 391 ₽/т, переменные расходы 1 000 ₽/т, резерв 100 млн ₽, перенос 50 млн ₽. Мощность 68 млн т/кв., ремонт −4, резерв +3. На 27 окнах 2013Q1–2026Q2 вклад равен +282 млн ₽, постоянный резерв даёт −696,125 млн ₽. Это дополнительный операционный результат сценария до прочих расходов и налогов, не подтверждённая прибыль портов. Основания параметров, формулы и чувствительность: [Экономика сценария](../04%20Проверка/Экономика%20сценария.md).


## Опубликованные мощности

В `/api/replay` можно передать `capacityMode: "published"`. Годовая установленная мощность берётся из проверенного бассейнового архива только для указанного года реконструкции. Квартальный эквивалент равен мощности / 4. При отсутствии среза окно пропускается, список годов возвращается в `coverage.missingCapacityYears`. Значения разных годов применяются отдельно к каждому кварталу, включая окна через границу года. Режим `scenario` сохраняет условную постоянную мощность и прежние контрольные результаты.

`capacityAssumptions`, `capacityReferences` и `capacityKnownAtDecision` раскрывают происхождение и ограничения. Источники мощности могут быть опубликованы после исторической даты решения. Поэтому published - реконструкция при фактическом годовом показателе, а не строгая проверка решения исключительно на доступной тогда публичной информации. Данные потока для прогноза по-прежнему ограничены датой публикации. Ремонт, резерв и затраты остаются параметрами сценария.

Файлы, страницы первичных PDF и границы покрытия: [CAPACITIES.md](data/CAPACITIES.md). На `/data` есть таблица всех лет, ссылки на первоисточники и сохранённые копии. Общероссийский ряд мощности 2000-2024 показан отдельно от трёх бассейнов.
